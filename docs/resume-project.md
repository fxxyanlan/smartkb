## 🔧 待你实测填入的数字（半天搞定）

**1. 接口用例数 X**
按上面第2条的场景写用例清单（表格即可：用例编号/前置条件/步骤/预期/实际），数一下多少条。Postman 里建个 collection 跑一遍截图留证。

**2. 三个缺陷的复现方法**（我已从代码确认，删你动手跑一遍留证据）
- **缺陷A·删除返回错误**：`curl -X DELETE http://localhost:8000/api/v1/documents/不存在的id` → 返回200和deleted_chunks:0，正确应返回404。根因：服务层从不抛KeyError，接口层的404处理永远走不到。
- **缺陷B·伪造文件500**：随便一个文件改名成 .pdf 上传 → 服务端500。正确应返回400"文件损坏"。根因：只校验了扩展名，没校验文件内容，解析失败被当成服务端错误。
- **缺陷C·重复上传**：同一PDF传2次 → 文档列表出现2条，引用重复。根因：入库无去重逻辑。（你之前库里那6份重复PDF就是这个问题的现场证据！）
- 每个缺陷写一条缺陷记录：现象/复现步骤/日志/根因/修复建议。这三张纸就是你面试时"发现并推动修复"的底气。

**3. 20题评估集 → 准确率、拒答率**
针对你上传的文档出20题：10题文档里有答案、5题明显超纲、5题表述模糊。逐题提问打分：
- 可答10题：答案与出处一致算对 → 准确率 = 对的/10
- 超纲5题：模型明确说"文档中没有"算拒答成功 → 拒答率 = 成功/5
- 模糊5题：记录回答行为（追问/部分回答/瞎答）

**4. 首字响应时间 X 秒**
```powershell
curl.exe -N -X POST http://localhost:8000/api/v1/chat/stream -H "Content-Type: application/json" -d '{"question":"你的测试问题"}' -w "%{time_starttransfer}"
```
跑3次取平均。
