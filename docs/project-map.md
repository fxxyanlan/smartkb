# 项目地图（人话版）

> 看不懂目录和代码时打开这份文档。每一行都是"一句话作用"，不用背，用到哪个查哪个。

## 一、先记住一个比喻：这个项目是一家餐厅

你问 AI 一个问题，就像去餐厅点菜：

```
你（顾客）
  → frontend/        服务员：端茶倒水，接你的话（网页界面）
  → app/api/         点菜单传递员：把你的问题写成单子送到厨房
  → app/services/    领班：安排后厨按步骤干活
  → app/core/        后厨：真正做菜的地方
  → DeepSeek         外卖中央厨房：最后把菜名变成成品（生成答案文字）
  ← 原路端回来给你，还附上"食材来源"（引用的文档片段）
```

## 二、根目录下的东西

| 名字 | 是什么 | 要看吗 |
|---|---|---|
| `.venv/` | 虚拟环境，装的所有第三方包（别人写的代码） | ❌ 别看别动 |
| `app/` | **后端**，全部核心逻辑都在这 | ✅ 主要看这个 |
| `data/` | 自动生成的数据：下载的模型文件、向量数据库 | ❌ 别手动改 |
| `docs/` | 文档（架构说明、演示指南、吃透计划、本文件） | 📖 需要时翻 |
| `frontend/` | **前端**，浏览器里看到的网页 | ✅ 要看 |
| `logs/` | 运行日志，出 bug 时来这查线索 | 🔍 排错时看 |
| `tests/` | 测试代码，验证功能没坏 | ⏸ 暂时不管 |
| `.env` | 密钥和配置（DeepSeek 的 key 在这） | ⚠️ 别发给任何人 |
| `.env.example` | .env 的"空白模板"，给别人参考用的 | 不用管 |
| `.gitignore` | 告诉 git 哪些文件不用上传 | 不用管 |
| `pyproject.toml` | 项目依赖清单（要用哪些第三方包） | 📖 装包时看 |
| `README.md` | 项目说明书，面试官第一个看的就是它 | ✅ 熟悉它 |

## 三、app/ 里面的东西（后端）

### 三个"门面"文件

| 文件 | 一句话作用 |
|---|---|
| `app/main.py` | 总开关。程序从这启动，把 api/ 下三个路由文件接上，再把 frontend/ 挂载出去 |
| `app/config.py` | 设置面板。读 .env 里的密钥、端口、模型路径，给全项目用 |
| `app/api/schemas.py` | 定义"请求和回复的格式"，相当于点菜单的固定格式 |

### app/api/ —— 前台（接 HTTP 请求的地方）

| 文件 | 一句话作用 |
|---|---|
| `app/api/documents.py` | 管"传文档"：上传 PDF/Word、列出文档、删除文档 |
| `app/api/chat.py` | 管"问问题"：接收问题，把答案流式（一个字一个字）推给网页 |
| `app/api/health.py` | 管"还活着吗"：一个测试接口，访问它能确认服务启动成功 |

> 这个文件夹只干一件事：收请求、叫 services 干活、把结果还回去。**它自己不做真正的逻辑。**

### app/services/ —— 领班（安排流程的地方）

| 文件 | 一句话作用 |
|---|---|
| `app/services/ingestion.py` | 收文档的流程：调用 loaders 读文件 → 切块 → 调 embeddings 变数字 → 存进向量库 |
| `app/services/chat_service.py` | 答问题的流程：去向量库找相关片段 → 拼提示词 → 调 DeepSeek → 组织回答和引用 |

> 领班自己不做菜，它只决定"先做什么后做什么"。

### app/core/ —— 后厨（真正干重活的）

| 文件 | 一句话作用 |
|---|---|
| `app/core/loaders.py`（在 utils/） | 读文件的：PDF 用 PyMuPDF 读，Word 用 python-docx 读 |
| `app/core/embeddings.py` | 把一段文字变成一串数字（向量），语义相近的文字数字也相近 |
| `app/core/vector_store.py` | 向量仓库：存进去、按相似度找出来、删掉、列出所有文档 |
| `app/core/rag.py` | 大厨：把"检索到的片段 + 你的问题"组装成提示词，调用大模型 |
| `app/core/llm.py` | 专门跟 DeepSeek 打交道的，一个普通对话、一个流式对话 |
| `app/core/prompts.py` | 提示词模板，规定 AI"只根据材料回答，并标注引用" |

### app/utils/ —— 工具箱

| 文件 | 一句话作用 |
|---|---|
| `app/utils/loaders.py` | 读 PDF/Word 文件，把文字抽出来 |
| `app/utils/logging.py` | 日志设置，决定打印什么信息、写进哪个文件 |

## 四、frontend/ 里面的东西（前端）

| 文件 | 一句话作用 |
|---|---|
| `frontend/index.html` | 页面骨架：标题、输入框、按钮、聊天区（只有结构，没有行为） |
| `frontend/style.css` | 化妆师：决定页面长什么样子（颜色、间距、引用卡片样式） |
| `frontend/app.js` | 行为：你点发送 → 它把问题发给后端 → 一个字一个字收回答 → 渲染到页面和引用卡片 |

## 五、"打开代码看不懂"怎么办（三招）

**第一招：先看文件最上面的三引号说明。**
这个项目每个文件开头都写了 docstring（文档字符串），用一句中文说了它是干嘛的。

**第二招：只看函数名，不抠每一行。**
一个文件就像一个部门，函数名就是员工工牌。先扫一遍有哪几个函数（PyCharm 左侧 Structure 面板能看到全部函数列表），比如 vector_store.py 里就 4 个：`add`（存）、`search`（找）、`delete`（删）、`list_docs`（列）。知道谁是谁就够了，具体代码等你改的时候再细看。

**第三招：顺着一条链路走一遍，别东看一眼西看一眼。**
最有效的方式是跟着"一个问题"的旅程走：
1. `frontend/app.js` 里 `sendQuestion` —— 问题从这发出
2. → `app/api/chat.py` 的 `/chat/stream` —— 后端在这接住
3. → `app/services/chat_service.py` 的 `stream_answer` —— 领班安排
4. → `app/core/rag.py` —— 检索 + 拼提示词
5. → `app/core/llm.py` —— 调 DeepSeek
6. → 原路返回，`app.js` 把每个字画到页面上

走通这一条链，你就看懂了这个项目 80% 的核心。剩下的（配置、日志、健康检查）都是脚手架，不用天天看。

## 六、日常只需要盯的 5 个文件

| 文件 | 为什么重要 |
|---|---|
| `app/core/rag.py` | RAG 的心脏，面试必问 |
| `app/services/chat_service.py` | 问答流程的调度 |
| `app/core/vector_store.py` | 向量存取，检索原理在这 |
| `app/api/chat.py` | 流式接口（SSE），加分项 |
| `frontend/app.js` | 前端怎么消费流式数据 |

把这 5 个文件能讲明白，这个项目你就"吃下"了。
