## 二、测试策略

采用**两层测试策略**：

1. **确定性层（自动化测试）**：用内存替身（`FakeStore` / `FakeLLM` / `FakeEmbedder`）隔离外部依赖，覆盖业务分支与异常路径，**可重复、毫秒级**。
2. **真实性层（端到端实测）**：真实 Embedding + 真实 Chroma + 真实 HTTP 链路，验证检索质量、接口契约、SSE 协议、去重与错误码。

> LLM 生成节点先以**桩模型（StubLLM）**验证链路与契约（第 4.1–4.4 节）；随后在**有效 API Key** 下完成真实 DeepSeek 全链路复测（第 4.5 节），鉴权失败路径单独做真实探测（期望 503）。

## 四、真实链路端到端实测

### 4.1 测试集与样本

- 样本文档：一份 Markdown（`faq.md`，含系统概述、技术选型、检索参数、防幻觉策略、接口清单）。
- 评估集 8 题：5 题「可答」（答案在文档内）、2 题「超纲」、1 题「模糊」。

### 4.2 接口契约测试

| 用例 | 请求 | 预期 | 实测 | 结论 |
|---|---|---|---|---|
| E2E-01 | 上传 faq.md | 200，status=ingested | 200，`ingested`，2 chunks | 通过 |
| E2E-02 | 再次上传同一内容 | 复用，status=exists | 200，`exists`，同一 doc_id | 通过 |
| E2E-03 | 列出文档 | 1 条 | 1 条（去重生效） | 通过 |
| E2E-04 | 普通问答 | 含 answer/citations/conversation_id | 字段齐全，citations=2 | 通过 |
| E2E-05 | 多轮追问（带 conversation_id） | 同一会话 | conversation_id 一致 | 通过 |
| E2E-06 | 流式问答 | 首条为 delta，末条为 done | 协议符合 | 通过 |

### 4.3 检索准确性（真实 Embedding + 真实向量检索，hit@4）

| Q2 | 可答 | 系统默认检索几段内容？ | ✓ | 0.519 |

### 4.5 真实 DeepSeek 全链路复测（有效 Key）

更新有效 API Key 后，用同一份样本文档跑完整链路（真实检索 + 真实 DeepSeek 生成）：

| 编号 | 类型 | 问题 | 判定 | 延迟 | 引用 |
|---|---|---|---|---|---|
| Q1 | 可答 | AskDocs 使用哪个大语言模型？ | ✓ | 1282 ms | 2 |
| Q2 | 可答 | 系统默认检索几段内容？ | ✓ | 719 ms | 2 |
| Q3 | 可答 | 向量数据库用的是什么？ | ✓ | 992 ms | 2 |
| Q4 | 可答 | 分块大小和重叠分别是多少？ | ✓ | 1600 ms | 2 |

| Q6 | 超纲 | 今天北京的天气怎么样？ | ✓（拒答） | 491 ms | 2 |
| Q7 | 超纲 | 请用 Python 写一个快速排序函数。 | ✓（拒答） | 567 ms | 2 |

## 六、测试结论

- **功能**：核心链路（上传→解析→分块→向量化→检索→生成→引用）全部打通，异常路径状态码语义正确。
- **质量**：自动化测试 50 用例全绿，覆盖率 92%，ruff 零告警。
- **稳定性**：真实栈端到端连续运行无崩溃；错误场景均返回友好且语义正确的响应。
- **可重复**：确定性层测试不依赖网络与外部服务，可在 CI 直接运行。

**遗留局限（如实声明）**：

1. `llm.py` 覆盖率 61%，真实上游分支（网络超时等）无法在单测中稳定覆盖；错误翻译分支已用 mock 覆盖。
2. 真实复测基于单一样本文档与 9 题评估集，样本量有限，非大规模评测集。
