# AskDocs 吃透计划（口语版）——从"抄会了"到"讲得清"

> 目标只有一个：面试官问"你这项目怎么回事"，你能用大白话讲 5 分钟，  
> 他再往深追，你也接得住。
>
> 原则：**先说人话，再挂术语。** 术语都是行业通用词，面试官都懂，  
> 但你要先用大白话证明自己懂，术语只是最后贴的标签。

---

## 第一部分：5 天计划（每天 40 分钟）

### Day 1 —— 讲清楚"一次问答的全旅程"

不看代码，对着手机录音讲这个题目：

> "用户在浏览器输入一个问题，到看到答案一个字一个字蹦出来，中间发生了什么？"

讲完回听，对照下面的清单打勾（每条都是人话，括号里是对应的术语，讲的时候可以先说人话再补术语）：

- [ ] 前端把问题打包发出去（发的是个 POST 请求到后端的问答接口，body 里带着问题和一个"这是第几次对话"的编号）
- [ ] 后端先检查这个请求格式对不对（用 Pydantic 做校验，格式不对直接打回）
- [ ] 问题先被翻译成一串数字（Embedding 向量化，512 个小数）
- [ ] 拿这串数字去仓库里找"意思最接近"的几段文档（向量检索，只捞最相关的前 4 段，这个"前几名"的数量就是 top_k）
- [ ] 找到的几段拼成一段"参考资料"，连同指令一起塞给大模型，指令大意是："只准根据这些资料回答，资料里没有就说不知道"（这段指令就是 system prompt）
- [ ] 大模型一个字一个字地往回吐答案（流式生成），后端每收到一小段就立刻转发给浏览器，不等全部写完
- [ ] 每一小段答案被包成固定格式的消息推过去（SSE 协议，每条消息长这样：`data: {...}` 后面跟两个换行）
- [ ] 浏览器把收到的字节攒着、按规则切开、逐字贴到页面上（打字机效果）
- [ ] 答案流完了，后端补发最后一条消息，里面带"参考了哪些文档段落"和"本次对话编号"（引用列表 + conversation_id）
- [ ] 前端把引用画成卡片贴在答案下面，并记住对话编号——下次提问带上它，模型才记得前面聊过什么（多轮对话）

**过关标准**：一遍能把这 10 步讲全，不看材料。

---

### Day 2 —— 讲清楚"上传入库的全旅程"

同样方法，讲：

> "用户点上传选了个 PDF，到它能被搜到，发生了什么？"

清单：

- [ ] 前端把文件打包传给后端（multipart 表单上传）
- [ ] 文件先存到服务器硬盘上一个文件夹里（`data/documents/`）
- [ ] 后端看文件后缀名决定用哪个工具拆开它：PDF 用一个库、Word 用另一个（PyMuPDF / python-docx，这就是"路由分发"）
- [ ] 整份文本被切成一段一段的，每段大约 500 字，而且**相邻两段之间故意留 50 字重复**——为什么留？防止一句话正好被切在两段的分界线上，那样两段都不完整，检索就漏了（chunking，分块）
- [ ] 每一段被翻译成一串数字（还是 Embedding，这次是批量转）
- [ ] 数字 + 原文 + 标签一起存进仓库（标签记着"这段来自哪份文件、文件叫什么"——以后删文件、显示引用全靠这个标签）

**过关标准**：能答上这两个问题——

1. "为什么要切段，整篇直接存不行吗？"（因为提问时只捞相关的几段喂给模型，不切就没法精准捞；而且模型一次读不了那么长）
2. "为什么相邻段要有重叠？"（防止关键句被切分线劈成两半）

---

### Day 3 —— 改参数做实验（建立"手感"）

每改一处，重启服务问同一个问题，前后对比。**做完每个实验写一句话结论，这 4 句话就是面试谈资。**

| 实验     | 怎么改                      | 你会看到什么              | 一句话结论（示例）                |
| ------ | ------------------------ | ------------------- | ------------------------ |
| 只捞 1 段 | config.py 里 `top_k` 改成 1 | 引用卡片只剩 1 条，答案明显变薄   | "捞太少先得不够用，答案缺胳膊少腿"       |
| 切得粉碎   | 分块大小改成 50 字              | 检索到的片段都是半截话，答非所问    | "块太小上下文断裂，检索到也用不上"       |
| 放飞自我   | 模型温度（temperature）改 1.0   | 同一个问题问两遍，答案措辞明显不同   | "温度高=随机大，创意任务才调高，问答类要调低" |
| 撒手不管   | 把提示词里"只根据资料回答"删掉         | 问库里没有的问题，模型开始一本正经瞎编 | "那句话就是防幻觉的安全带，删了必翻车"     |



---

### Day 4 —— 故意弄坏它（制造报错，见世面）

**报错是最好的老师。你之前怕报错，是因为从没主动制造过。** 每弄坏一处，跑起来看报什么错，看完恢复原样（用 `git checkout 文件名` 一键还原）：

| 弄坏哪里         | 怎么弄                  | 会发生什么                            | 学到什么                              |
| ------------ | -------------------- | -------------------------------- | --------------------------------- |
| 消息记录被删一条     | 在对话逻辑里注释掉"记录"那行      | 后端直接报错拒绝                         | 对话记录必须首尾连贯，缺一段协议都不答应              |
| 推送的消息少了结尾符   | 把每条消息结尾的"两个换行"改成一个   | 前端解析不出任何内容，页面死掉                  | 那两个换行是消息的"边界记号"，没了就分不出哪条是哪条       |
| 解码器忘了说"后面还有" | 前端解码参数去掉 stream:true | 答案里随机出现乱码方块                      | 一个汉字在网络上可能被劈成两半，得告诉解码器"别急着断字"     |
| 去掉安全转义       | 前端直接插入原文不转义          | 上传个文件名叫 `<img src=x>` 的文件，页面行为异常 | 用户可控的内容必须转义，否则别人能往你页面里塞代码（XSS 攻击） |

### Day 5 —— 模拟面试

拿着 Day 3、Day 4 写下的结论，去答 demo-guide.md 里那 5 道面试题。要求：**每题先用大白话答，答完再补一句"行话叫 XX"。** 录音回听。

## 第二部分：自测题库（全部口语化，答不上来 = 回去看代码）

> 用法：每题先用人话答，术语记不住没关系，意思对就算过。

### A. 核心思路（8 题）

1. 这个项目解决什么问题？如果不用这套做法、直接问大模型，会出什么事？
2. "先查资料再回答"这整个流程，行话叫什么？（RAG）它比"直接问"好在哪？
3. 长文档为什么要切成小段？切太大、切太小各有什么毛病？
4. "每段约 500 字、相邻段重叠 50 字"——重叠那 50 字是干嘛的？
5. 把一句话变成一串数字，这步行话叫什么？（Embedding）变完之后有什么神奇特性？
6. 怎么判断两句话意思近不近？为什么用"方向像不像"而不是"距离远不远"来比？
7. 什么叫"一本正经地瞎编"？（幻觉）这个项目用了哪几招防它？
8. 每次只捞前 4 段相关文档——为什么是 4？捞 1 段和捞 40 段各有什么代价？

### B. 仓库那层（5 题）

1. 存数字、找"最接近"的仓库（向量数据库），跟存姓名电话那种普通数据库，本质区别是什么？
2. 数据存在内存里和存在硬盘上有什么区别？重启服务后各会发生什么？（持久化）
3. 入库时每段存了哪三样东西？如果"这段来自哪份文件"这个标签忘了存，以后哪些功能会废掉？
4. 检索回来的结果带一个"像不像"的分数，为什么代码里要做一步减法换算？
5. 删除一份文档时，怎么保证它所有的段都被删干净？（提示：靠入库时打的标签）

### C. 后端那层（6 题）

1. 函数前面加 `async` 是什么意思？什么时候必须加？（跟"等外部服务响应时不闲着"有关）
2. 前端发来的请求乱七八糟，后端第一道关是什么？格式不对会怎样？
3. 普通接口是"攒齐了再一次性给"，流式接口是"有一点点就给一点点"——实现上用的什么响应方式？
4. 代码为什么分四层文件夹放（接口/核心/工具/服务）？全塞一个文件里不是也能跑？分层的实际好处是什么？
5. 密钥为什么放在一个单独的配置文件里而不是写在代码里？上传代码仓库时怎么保证它不被泄露？
6. 别人拿到你的开源代码想跑起来，他缺什么？（提示：配置文件模板和真实文件的区别）

### D. 打字机效果那层（6 题）

1. 不做流式，用户的体感是什么？流式解决的是"真的变快了"还是"感觉不卡了"？
2. 服务器推给浏览器的每条消息长什么样？（以 `data:` 开头，结尾有两个换行）
3. 前端收到字节为什么不能立刻解析、要先攒一攒？（一块数据里可能掺着半条消息）
4. 解码时忘了说"后面还有数据"，会出什么毛病？为什么偏偏中文容易出？（一个汉字占多个字节，可能被劈成两块）
5. 服务器单向推、浏览器只听——这种场景为什么要选简单的方案而不是双向通信的方案？（WebSocket 杀鸡用牛刀，这题面试爱考）
6. "这是第几次对话"的编号是谁生成的、怎么传回前端的、下一轮带着它有什么用？

### E. 前端和安全（2 题）

1. 逐字贴到页面上，浏览器这边是怎么一步步读网络数据的？
2. 有人上传一个文件名里藏代码的文件，你的系统为什么不怕？（转义：把特殊符号变成无害文字）

---

## 使用规则

- 每天 40 分钟，别贪多
- 答题标准只有一条：**说人话，意思对**
- 答不上来的题，回到对应文件读代码，再用自己的话重答
- 5 天后终测：A 组 1-8 题全过 = 这个项目真正属于你了

| 服务器一边生成一边推字，打字机效果   | 流式输出（SSE）         |
| 模型一本正经地编造           | 幻觉（hallucination） |
| 用 Python 写后端接口的框架   | FastAPI           |
